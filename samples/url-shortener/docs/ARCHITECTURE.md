# Architecture — URL Shortener

Add an optional ExpiresAt to ShortUrl. Create computes ExpiresAt = now + expiresInMinutes using TimeProvider. The redirect path caches a CachedLink (target + expiry) and evaluates expiry on every request, returning 410 Gone for expired links without recording a click. Metadata and create responses expose expiresAt. No new endpoints.

## Components
- **Platform kit** (template-locked): database (EF Core, provider-switchable), cache (`ICacheService` + circuit breaker), bounded background queue, rate limiting, request timeouts, health checks, ops stats.
- **Feature code** (`src/App/Features/**`): generated by the orchestrator's agents and validated by its gates.

## Architecture decisions
### ADR-001: 410 Gone for expired links
- **Decision:** Return 410 with problem details instead of 404.
- **Rationale:** Tells clients the link existed but is permanently unavailable; distinguishes expiry from typos.
- **Alternatives considered:** 404 (hides existence); redirect to an 'expired' page (needs UI, out of scope).

### ADR-002: Relative expiry input, absolute storage
- **Decision:** Accept expiresInMinutes, store absolute ExpiresAt (UTC).
- **Rationale:** Avoids client clock skew and time-zone mistakes; absolute storage makes the check a simple comparison.
- **Alternatives considered:** Accept absolute expiresAt from clients.

### ADR-003: Check expiry on every request
- **Decision:** Cache the expiry with the target and compare on each redirect; keep cache TTL unchanged.
- **Rationale:** A cache entry can never serve an expired link, and no DB round-trip is added on cache hits.
- **Alternatives considered:** Shorten cache TTL to the remaining lifetime (more DB load, still racy across instances).

### ADR-004: Keep expired rows
- **Decision:** Expired links are not deleted.
- **Rationale:** Statistics stay queryable; purge policy can be added later with the retention setting.
- **Alternatives considered:** Delete on expiry (loses analytics).

## Risks
- Production databases need an EF Core migration adding the nullable expires_at column (development SQLite is recreated).
- With a shared Redis cache, entries written by the previous version have a different shape; bump the cache key prefix when deploying.

## Assumptions
- Read:write ratio 100:1 (typical for read-heavy services).
- Data retention 90 days.
- Peak traffic = 10× the daily average.

## Strategies for this profile
- Stateless API instances behind the YARP gateway (scripts/run-cluster.ps1) to demonstrate scale-out on one host.
- Cache-aside on the read path (ICacheService) — redirects rarely touch SQLite.
- Analytics written off the request path in batches (bounded queue with load shedding).
- SQLite WAL: many concurrent readers, one writer — the write path is the ceiling.
- Rate limiting per client and request timeouts protect the single host.
